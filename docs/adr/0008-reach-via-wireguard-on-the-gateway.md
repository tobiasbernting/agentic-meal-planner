# Reach from outside the home: WireGuard on the household gateway, not a relay

---
Status: Accepted (owner, 2026-10-18). Supersedes the Trello half of ADR-0006 and the reach half of ADR-0007.
---

The household wants one shopping list, edited by both parents from the store and from home, without the server being exposed to the internet. We considered pushing the list through a cloud relay (an event stream or hosted store that both the phones and the server connect to outbound) and rejected it. Instead the phones reach the LAN through a WireGuard tunnel hosted on the household's UniFi gateway, with the WireGuard app's On-Demand rule so the tunnel is up whenever the phone leaves home Wi-Fi. The app stays exactly what it is: one server-rendered htmx app on the LAN (ADR-0002), reached by a LAN name that Pi-hole resolves over the tunnel. Nothing in the application changes for this; the whole decision lives in the deployment.

Considered and rejected:
- **A cloud event stream (Kafka-style).** Browsers cannot speak Kafka, and a stream is transport, not state: a phone opening the list cold in the store still needs something in the cloud holding the current list. That forces a hosted store, which is the next option.
- **A hosted store as the list's source of truth (Firestore or similar), the server as one more peer.** Works even when the home box is down, but the Shopping List page would have to become a client-rendered island with its own sync model, a second data model would exist beside SQLite, every self-hoster would need a provider account and config, and the list text would sit with a third party. Too much machinery for a grocery list.
- **Tailscale.** Easiest tunnel and it gives a real certificate for free, but the household prefers to host its own tunnel and already has a gateway that can.
- **UniFi Teleport.** Same WireGuard underneath with a one-tap invite, but the user must tap Connect every time and it drops silently. On-Demand in the WireGuard app makes the tunnel invisible, which matters more than onboarding for a non-technical user.
- **A cloud shopping list app as the sink (Trello).** This was ADR-0006. The household wants add, remove and tick in one place, and the pushed board cannot restore Dish-derived lines. With the LAN reachable from the store, the Trello sink has no job left and is removed. The generic webhook sink stays, since it is cheap and contributors use it.

Consequences: the app is served over plain HTTP on its `.lan` name, because Let's Encrypt cannot issue for a private TLD and the owner does not want to buy a domain or install a private CA on each phone right now. Over WireGuard the traffic is encrypted anyway. The cost is that the service worker of ADR-0007 is inert for this household (browsers only install one over HTTPS): no Offline Copy and no Pending Changes until the deployment gains HTTPS, by a bought domain with DNS-01 or a private CA. The offline code stays in the repo, dormant here and live for self-hosters who serve HTTPS; the built-in certificate (#110) remains open for them. The phone's WireGuard config must hand out Pi-hole as DNS, or the `.lan` name does not resolve away from home. When the home box is down, the tunnel stays up but the app is unreachable; the household accepts that. The UniFi tunnel replaces the WireGuard container in the homelab, which is retired once both phones are on the new tunnel.
